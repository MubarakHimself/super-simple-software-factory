# App audit 2026-08-13 - "a lot of unnecessary stuff in there"

Directed audit of the SDL Factory desktop app, done by **using** it: Electron launched with
`--remote-debugging-port=9222`, driven over CDP, every surface and state visited and its full DOM
text read. Nothing was fixed; nothing was committed. `apps/ui/server/`, `adws/adw_modules/` and the
skill templates were not touched. No Anthropic call was made by this audit.

**Surfaces visited:** Board (empty), Trace (populated - see F1), Gate (empty), Settings (all five
panes incl. Server), Terminal (tabs, profiles dropdown, folder picker, status chip, live pty),
the setup drift banner (both the appears-and-then-vanishes paths), the Setup screen (`file://`
`dist-setup/setup.html`, full checklist), the command palette (Ctrl+K on all five surfaces), and
keyboard shortcuts 1-5.

Ranked by how much operator time and trust each one costs.

---

## F1. The app fills the operator's Trace list with its own smoke tests, and spends real tokens doing it

**Where:** `electron/main.ts` `runBackgroundSetupCheck()` -> `detectSetup()` ->
`uv run installer/install.py --verify-only --json`, on **every launch**; the same call is made
again by `SetupScreen`'s mount effect. `installer/steps.py:1688` - verify check **V2** is a real
`adw_prompt` round trip against the test lane, which writes a real session row into `sssf.db`.

**Evidence**

```
start of audit                        SESSIONS = 8
after 2 app launches + 2 Setup visits SESSIONS = 12
GET /api/sessions?limit=200 -> 12 rows, requests grouped:
     12 "request":"reply with the single word OK"      <- 12 of 12
V2 message on this box: "round trip ok: adw_id=72c70c08 status=success total_tokens=39501"
T+8s after launch, dashboard first paint:
  rail badge Trace = 1     row 356da654 "reply with the single word OK"  Running
```

**Why it hurts:** Trace is the one surface that must show the operator's work, and 100% of it is
the installer's own probe. The rail's running-count badge reports factory activity that is really
the app checking itself. The default landing route is `/trace` with no id, which auto-selects
`sessions[0]` - so the app opens onto its own smoke test, every time. And it is real spend on
every launch, against MAP rule 7.

**Fix:** stop the launch-time drift check from taking the token-spending path (a
`--verify-only --no-round-trip` style flag in the wizard), or stamp installer-originated runs
(`origin=installer`) and hide them from the sessions list by default. **Effort: M** (S if the UI
just filters them; the honest fix touches `installer/`).

## F2. Switching surfaces kills every open terminal session

**Where:** `App.tsx` returns a *different* element tree per surface, so React unmounts the whole
`Shell` subtree on navigation; `PtyPane`'s cleanup calls `window.factory.term.close(sessionId)`.

**Evidence** (live, one run)

```
A. Terminal, clicked "+ Shell"   -> tab "Shell", chip PLAIN, cwd C:\Users\Mubarak, xterm count 1
B. clicked Board                 -> xterm count 0
C. clicked Terminal              -> "no terminals open", xterm count 0
```

**Why it hurts:** the whole point of the profiles is `claude` - "the operator's day harness".
Glancing at Trace or the Board for two seconds destroys the conversation. Spec 3.4 promises
backscroll survives a *tab* switch; nothing survives a *surface* switch. This is the concrete
mechanism behind "it's a cluster": the Terminal is not a place you can leave and come back to.

**Fix:** mount `TerminalSurface` once, above the per-surface switch (keep it in the tree and toggle
`display`), the same trick it already uses between its own tabs. **Effort: M.**

---

## F3. The sidebar column is mandatory on all five surfaces; on three it is dead chrome (operator finding #1)

**Where:** `Shell.tsx` always renders `<ResizablePanel id="sidebar" defaultSize={260}
minSize={180}>` - there is no collapse, no zero width, and no "no sidebar" path.

**Measured:** 260px of 1360px = **19% of the window**, on every surface.

| Surface | What is in the 260px | Verdict |
|---|---|---|
| Trace | run list + filter box | **keep** - this is the run list's home |
| Settings | 5 anchor links to the sections below | keep (real hierarchy) |
| Board | `QUEUE 0`, an "all columns" button, 4 status rows all `0` | duplicates the column headers; when empty the columns are not even rendered |
| Gate | `WAITING ON GATE 0` / `nothing waiting` | says the same thing the main pane says at length |
| Terminal | one static, non-interactive paragraph | pure waste - and wrong (F4) |

**Why it hurts:** the operator reads the column as "the sessions panel that follows me around."
On Terminal it costs a fifth of the xterm width to display a sentence.

**Fix:** make `sidebar` genuinely optional in `Shell` (render the panel and its handle only when a
surface passes one); drop it on Terminal and Gate; on Board keep a card list only - the status
counts already live in the column headers. **Effort: S** for Shell + Terminal + Gate.

## F4. The Terminal sidebar contradicts the Terminal

**Evidence** - two sentences, 260px apart, on the same screen:

```
sidebar : "... Default working directory is the repo root."
main    : "Start a plain shell in your home folder ..."
live    : term.open("shell") -> { cwd: "C:\\Users\\Mubarak", status: {factory:false, docs:false} }
tab chip: PLAIN   C:\Users\Mubarak
```

Spec 3.3a made home the **only** default and deleted the repo-root mode; the sidebar text was never
updated. **Fix:** deleting the sidebar (F3) deletes the wrong sentence with it. **Effort: S.**

## F5. The setup drift banner disappears on the first click and usually never appears at all

**Where:** `SetupDriftBanner` lives inside `Shell`, holds its status in local `useState`, and
subscribes to a **one-shot** `setup:drift` IPC event that main sends exactly once, ~60s after the
window shows (the check is slow because of F1's round trip).

**Evidence** (two launches, contrasted)

```
launch A - navigated during the check window:
  main log: "background setup check: not converged (exit 1) - notifying the dashboard"
  DOM     : banner NEVER rendered, on any surface, ever
launch B - left alone:
  T+80s   : "Setup found 2 issues on this machine.  [Open Setup] [Dismiss]"
  click Board  -> banner: false
  back to Trace-> banner: false      (gone permanently)
```

**Why it hurts:** the one non-blocking way the app tells the operator his machine has drifted is
lost by the act of using the app. **Fix:** hold the drift status above the per-surface tree (App
state or a module store the banner reads). **Effort: S.**

## F6. "2 issues" is one issue - `expected-unavailable` is counted as a problem

**Where:** `Shell.tsx`: `status.checks.filter(c => c.outcome !== "ok")`.

**Evidence:** this machine's checklist is 5 `ok`, 1 `failed` (V6 `just not on PATH`), 1
`expected-unavailable` (V5, "expected-unavailable on Windows (no MSVC)"). The banner reports
**2 issues**. V5 is permanently expected-unavailable on Windows by design (MAP landmine), so on
this operator's laptop the banner can never reach zero and always overstates by one.

Same function: `detail = status.error ?? ...`, so a spawn failure renders as
*"Setup found spawn uv ENOENT on this machine."*

**Fix:** count `failed` + `needs-operator` only; wrap the error case in its own sentence.
**Effort: S.**

## F7. Setup is a one-way door

**Evidence:** the entire Setup screen offers five controls - `Re-check`, `Laptop`, `Server`,
`Container`, `Run setup (Laptop)`. There is no Back, no Skip, no Continue anyway. `setup:proceed`
is only ever called by an effect that fires when `converged === true`. The only machine that can
reach Setup is a drifted one, so the operator who clicks **Open Setup** on the banner is stuck
until he converges or restarts the app.

(The handler itself is unconditional - this audit escaped by calling `setup.proceed()` by hand.)

**Fix:** a "Back to dashboard" button calling the existing `setup.proceed()`. **Effort: S.**

## F8. Ctrl+K is not a command palette: dead on 3 of 5 surfaces, and it steals Ctrl+K from the terminal

**Evidence**

```
Gate     Ctrl+K -> "no matches"     (App passes no paletteItems)
Settings Ctrl+K -> "no matches"
Terminal Ctrl+K -> "no matches"
Trace    Ctrl+K -> 8 rows, all reading "reply with the single word OK"
placeholder on all of them: "Filter runs or queue items..."
```

It is a *filter*, bound to the universal *command palette* gesture, and it opens empty on the three
surfaces that have nothing to filter. Worse, `Shell.tsx` handles Ctrl+K **before** its own
`isTypingTarget()` guard, so it fires while focus is inside an input or an xterm pane - and Ctrl+K
is kill-to-end-of-line in readline and a live binding inside Claude Code.

Also inverted: palette rows show the hex `adw_id` as the primary label and the human request as the
sublabel, so eight runs look identical.

**Fix:** either make it a real palette (switch surface, new terminal, open Setup, jump to run/card)
or do not open it where there is nothing to filter; and let Ctrl+K through when a pty pane owns
focus. **Effort: S-M.**

## F9. Three names for one thing, three casings for one word

| Concept | Names in the UI |
|---|---|
| a factory run | **Trace** (rail) / **SESSIONS** (sidebar) / **trace** (breadcrumb) / **runs** ("Filter runs...", "No runs are waiting") / **run** ("Whole run") |
| the queue | **Board** (rail) / **QUEUE** (sidebar) / "The Board reads queue/*.md" |

Casing is inconsistent for the same word on one screen: rail tooltip `Trace`, sidebar header
`SESSIONS`, breadcrumb `trace`. **Fix:** one noun per concept, one casing rule. **Effort: S.**

## F10. Settings: two "paths" panes, one duplicated field

- `protected_files` is printed **verbatim twice** - Roster > defaults, and Observability.
- The db path is in Observability *and* behind the top bar's `db` chip.
- "Observability" holds db / journal_mode / poll_ms / session count / data_dir / sessions_dir;
  "Paths and process" holds bind address / port / build time / mode. That is one "where things
  live" pane split in two on no visible principle, with "Observability" as the label for a list of
  file paths.
- Server pane leads with `STATUS / not connected / [Connect]` **above** the `CONNECTION` form, so
  the first control offered on a never-configured app is Connect-with-no-host. The two headings
  ("Status", "Connection") are also near-synonyms.

**Fix:** merge into one "Paths and data" section, drop the duplicate, and put the form above the
status/Connect block. **Effort: S.**

## F11. There is no icon anywhere

`apps/ui/public/` is empty; `index.html` has no `<link rel="icon">`; `electron-builder.yml` has no
`icon:` key. Titlebar, taskbar, the packaged `.exe` and the browser tab all fall back to the
default Electron atom. MAP's UX-loop entry asks for this explicitly. Generation must stay pure-JS
(no MSVC on this box). **Effort: S.**

## F12. Stale and mislabeled chrome

- `electron-builder.yml` calls the app **"the operator's 'ADE'"** - MAP's operator ruling says it
  is explicitly **not** an ADE; documents repo detection as `justfile` + `adws/adw_data/sssf.db`
  (spec 4.3 changed it to `justfile` + `installer/install.py`); and cites `just ade-build`, a
  recipe that does not exist (it is `app-build`).
- The top bar's `Live / Paused / Stale . updated Ns ago` is the **sessions** poll's state. It is
  rendered on Board, Gate, Settings and Terminal, where it describes nothing on screen.
- The rail's count badges look identical but mean three different things: Board = *ready-for-agent*
  only, Trace = *running* only, Gate = *all* waiting. No legend.

**Effort: S.**

## F13. Clicking a Board card deletes the Board

`App.tsx`: `selected ? <QueueItemDetail/> : <BoardColumns/>`. Opening one card replaces the whole
Kanban with that card's raw markdown in a `<pre>`; the only way back is a small "all columns"
button in the sidebar. Board is also the one surface that never uses `Shell`'s inspector slot -
which is exactly where a card detail belongs. **Effort: M.**

## F14. Small repeats and dead weight (each S)

- Terminal says **"no terminals open"** twice on one screen (tab strip + empty state), and offers
  two differently-named buttons for one action: `+ Shell` and `New Terminal`.
- Setup shows a disabled **"Checking..."** button next to the line **"Checking this machine..."**.
- Trace's inspector keeps 5 tabs; for `adw_prompt` / `adw_scout` - the only chains the operator
  runs today - Gates and Diff are structurally always empty ("None ran for this phase.", "This run
  made no commits and captured no diff.").
- The run list falls back to the raw request when a run has no title, so 12 rows read identically;
  nothing distinguishes them but an 8-char hex id.
- Board's sidebar lists 4 statuses but not `Unparsed`, which the columns do show.

## Not a defect (checked, and clean)

- **ptys are real and correct.** `term.open("shell")` -> live `cmd.exe`, `echo AUDIT_MARKER_42`
  round-tripped through the bridge; replay-buffer ordering intact; the folder picker, the
  `PLAIN / factory / docs` chip and the profiles dropdown (Claude / Codex / pi) all behave.
- **No orphan processes.** After killing the app, no `cmd.exe` / `conhost.exe` / `OpenConsole.exe`
  had an electron parent or a dead parent traceable to it.
- **Keyboard 1-5** map cleanly to Board / Trace / Gate / Settings / Terminal, and digits typed into
  an xterm or an input do not navigate.
- **Inspector empty states are honest** - Gates and Diff both name why they are empty.
- **The origin gates hold.** Every action IPC is main-side; the Bun server was never involved.

## One factory-side observation (not UI)

The app's own verify reports **V6 `failed` - `{'just': 'just not on PATH'}`**, while MAP records
`just 1.58.0` as installed by the wizard on 2026-08-12. Whatever the truth, the operator now sees
it as a permanent orange banner. Worth resolving where it belongs, not in the UI.
