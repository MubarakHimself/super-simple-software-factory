Lane Balancer

adws/lane_balancer.py · 247 lines · last modified 2h ago by Grok 4.5

The lane balancer manages concurrent work lanes, each backed by a different model provider. It picks work from the Ready queue, assigns it to an available lane, and handles retry budgets with exponential backoff.

Architecture

The balancer runs as a single async loop. Each lane is a state machine with four states: idle, scouting, building, and reviewing. The balancer never dispatches work to a lane that's already active — it waits for a lane to return to idle before assigning the next unit.

The factory auto-picks from Ready. There is no dispatch button — the balancer is always watching.

Retry budget

Each lane has its own retry budget. When a unit fails, the balancer waits with exponential backoff (base 2s, factor 2, jitter ±20%) before retrying. After 3 consecutive failures, the lane parks for 5 minutes and the operator is notified in the morning brief.

class RetryBudget:
    max_retries: int = 3
    base_delay: float = 2.0
    factor: float = 2.0
    jitter: float = 0.20
    park_duration: float = 300  # 5 minutes

Cross-family review

When a unit reaches the review phase, the balancer assigns it to a reviewer from a different model family than the builder. This is enforced in select_reviewer():

def select_reviewer(builder_lane: Lane) -> Lane:
    candidates = [l for l in lanes
                  if l.role == "reviewer"
                  and l.family != builder_lane.family]
    return min(candidates, key=lambda l: l.queue_depth)

Merge queue

After review passes, the unit moves to the merge queue. The factory runs autonomously — no human ratification before code exists. The balancer does not merge automatically. It parks passed units in the queue and waits for the operator to bulk-merge in the Runs surface.

  • Autonomous planning — the planner locks its decision ledger and proceeds to code without human ratification. Cross-family review is enforced before merge.
  • Merge queue — the only human touchpoint. Passed runs queue up; the operator selects and bulk-merges to main, or parks any that don't match expectations.

Configuration

Lane configuration lives in config.py and can be edited per-project in Settings → Lanes. Each lane binds to a model and a role (workhorse or reviewer). The retry budget and max concurrent lanes are also configurable per project.
